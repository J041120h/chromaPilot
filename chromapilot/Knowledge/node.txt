Global Input Parameters
=================
1. <out_dir>
   Root output directory (absolute path required) for the entire workflow. Users only need to provide the top-level output directory once.
   Each function will automatically create and use its own step-specific subdirectory under <out_dir>, and when applicable, an additional sample-specific subdirectory, to organize intermediate files and final outputs.
   Therefore, <out_dir> should be understood as the root directory of the whole analysis rather than the final file location for an individual function.

2. <sample>
   Name of the single sample being processed.
   This parameter is used by functions that operate at the per-sample level.

3. <ref_genome>
   Reference genome identifier used to determine which genome assembly is used for downstream analysis.
   Only support 'hg38', 'mm10'(correspond to GRCh38, and GRCm38 genome assemblies respectively).
   - If user mentions 'hg38' or species keywords for human (e.g., 'human', 'Homo sapiens'), set 'ref_genome'='hg38'.
   - If user mentions 'mm10' or mouse keywords (e.g., 'mouse', 'mice',sapiens 'Mus musculus'), set 'ref_genome'='mm10'.
   - We do not support 'hg19' nor 'CRCh37'. If user mentioned keywords such as 'hg19' nor 'CRCh37', the agent should return error and ask the user to provide ref_genome again only in 'mm10' or 'hg38'

Global Output Parameters
=================
1. <log_out>
   Path to the log file containing all messages generated during function execution.

   All log files are stored under the centralized logging directory:
   - <out_dir>/log

   Log file names depend on whether the function operates at the sample level:
   - For sample-level functions:
     <out_dir>/log/<sample>_<function_name>.log
   - For non-sample-level functions:
     <out_dir>/log/<function_name>.log

Node Descriptions
=================

1. create_barcode_fasta
   - Input: 
      1. <input>
         Absolute path to input file containing barcode information (.xlsx/.xls or .csv/.tsv format). The file must contain a target column and a barcode column. Column names are detected case-insensitively (e.g. target, crf for targets; bc, barcode, sequence, index for barcodes). If column names are not found, the first two columns will be inspected and a constant-length A/C/G/T sequence column will be inferred as the barcode column.
      2. <out_dir>
         (see Global Input Parameters)
   - Output: 
      1. A dictionary containing:
         - 'barcode_fwd_fasta': Absolute path to forward barcode FASTA file
         - 'barcode_rev_fasta': Absolute path to reverse barcode FASTA file
         - 'log_out': (see Global Output Parameters) 
   - Function: 
      Create forward and reverse barcode FASTA files from a spreadsheet for demultiplexing, and this function does not require sample name to be specified.
   - Path Convention (relative to <out_dir>):
      Creates and writes into:
      - `barcode/`
      Output file names:
      - `barcode_fwd.fasta`
      - `barcode_rev.fasta`

2. demultiplex_reads
   This need to be conducted for each sample seperately
   - Input: 
      1. <barcode_fwd_fasta>
         Absolute path to FASTA file containing forward barcode sequences
      2. <barcode_rev_fasta>
         Absolute path to FASTA file containing reverse barcode sequences
      3. <sample>
         (see Global Input Parameters)
      4. <out_dir>
         (see Global Input Parameters)
      5. <fastq_r1>
         Absolute path to forward read FASTQ file (R1) for this specific sample
      6. <fastq_r2>
         Absolute path to reverse read FASTQ file (R2) for this specific sample
      7. <error_rate>
         Maximum allowed mismatch rate for barcode matching in cutadapt (default: 0)
   - Output: 
      1. A dictionary containing:
         - 'demux_dir': Absolute path to the directory containing demultiplexed FASTQ files after demultiplexing and symmetric barcode merging, or None if the process failed
         - 'log_out': (see Global Output Parameters) 
   - Function: 
      Demultiplex raw paired-end FASTQ files containing fragments with all barcodes for a single sample using forward and reverse barcodes, automatically remove empty barcode outputs, and merge symmetric barcode combinations generated by bidirectional fragment orientations into canonical barcode pairs.
   - Path Convention (relative to <out_dir>):
      Creates and writes into:
      - `demux/<sample>/`  (this is the returned 'demux_dir')

3. identify_adapter
   - Input:
      1. <fastq_dir>
         Absolute path to the directory containing paired-end FASTQ.gz files for this sample
      2. <sample>
         (see Global Input Parameters)
      3. <out_dir>
         (see Global Input Parameters)
      4. <cb>
         Cell barcode definition. Can be a fixed length (int), fixed sequence (str), or a list of candidate sequences (default: None)
      5. <sp>
         SPACER definition. Can be a fixed length (int), fixed sequence (str), or a list of candidate sequences (default: None)
      6. <umi>
         UMI definition. Can be a fixed length (int), fixed sequence (str), or a list of candidate sequences (default: None)
      7. <linker>
         LINKER definition. Can be a fixed length (int), fixed sequence (str), or a list of candidate sequences (default: ["GCGATCGAGGACGGCAGATGTGTATAAGAGACAG", "CACCGTCTCCGCCTCAGATGTGTATAAGAGACAG"])
      8. <error_rate>
         Maximum mismatch rate used to compute allowed mismatches per tag (default: 0.1)
      9. <laxity>
         Number of extra bases allowed when searching for the next adapter element (default: 0)
      10. <exclude>
         Comma-separated string specifying FASTQ prefixes to exclude before adapter identification (default: "unknown, IgG_control")
   - Output:
      1. A dictionary containing:
         - 'trimmed_dir': Absolute path to the output directory containing trimmed FASTQ files with adapter information annotated in read names, or None if processing fails.
         - 'log_out': (see Global Output Parameters)
   - Function:
      Identify adapter structures in paired-end FASTQ reads based on the user-defined
      schema, parse selected tag information such as CB and UMI, write CB/UMI values
      as SAM-compliant optional fields (CB:Z:.../UB:Z:...) in the read comment, trim
      adapter regions, and generate processed FASTQ files for downstream alignment.
   - Path Convention (relative to <out_dir>):
      Creates and writes into:
      - `trim/<sample>/`   (this is the returned 'trimmed_dir')

4. align_reads
   - Input:
      1. <fastq_dir>
         Absolute path to the directory containing paired-end FASTQ.gz files produced by upstream preprocessing steps
      2. <sample>
         (see Global Input Parameters)
      3. <out_dir>
         (see Global Input Parameters)
      4. <ref_genome>
         (see Global Input Parameters)
      5. <has_cb>
         Whether the FASTQ reads carry a CB:Z: tag in the read comment, to be used for CB-aware deduplication (default: False)
      6. <has_umi>
         Whether the FASTQ reads carry a UB:Z: tag in the read comment, to be used for UMI-aware deduplication (default: False)
      7. <min_length>
         Minimum fragment length allowed for valid paired-end alignments (default: 10)
      8. <max_length>
         Maximum fragment length allowed for valid paired-end alignments (default: 800)
      9. <picard_jar>
         Path to the Picard JAR file used for duplicate marking. If set to None, the path will be automatically detected from the active conda environment (default: None)
   - Output:
      1. A dictionary containing:
         - 'bam_dir': Absolute path to the output directory containing final deduplicated BAM files for this sample, or None if alignment fails
         - 'log_out': (see Global Output Parameters)
   - Function: 
      Align paired-end FASTQ reads to the reference genome using Bowtie2, perform duplicate removal according to the library design (coordinate-based, CB-aware, UMI-aware, or CB+UMI-aware), and generate coordinate-sorted and indexed BAM files for downstream analysis.
   - Path Convention (relative to <out_dir>):
      Creates and writes into:
      - `bam/<sample>/` (this is the returned 'bam_dir')

      2. <fastq_r1_list>
         List of absolute paths to R1 (forward) FASTQ.gz files, one per sample
      3. <fastq_r2_list>
         List of absolute paths to R2 (reverse) FASTQ.gz files, one per sample
      4. <out_dir>
         (see Global Input Parameters)
      5. <ref_genome>
         (see Global Input Parameters)
      6. <barcode_config>
         Path to BarcodeIdentification config file defining barcode structures and target names
      7. <dpm_fasta>
         Path to FASTA file containing DPM adapter sequences for cutadapt trimming
      8. <bpm_fasta>
         Path to FASTA file containing bead oligo sequences for cutadapt trimming

         Optional Path to barcode format file for validating barcode combinations (default: None)

      10. <umi_length>
         Length of the bead UMI sequence in BPM reads (default: 8)
   - Output:

   - Function: 
      Run the CHIP-DIP Snakemake pipeline to process paired-end FASTQ files into per-target split BAM files, including barcode identification, DPM/BPM read separation, adapter trimming, Bowtie2 alignment, and cluster-based splitting.
   - Path Convention (relative to <out_dir>):
      Creates and writes into:
      - `chipdip_prep/splitbams/<sample>/`  (this is the returned 'bam_dirs[sample]')
      Final split BAM file naming pattern:
      - `chipdip_prep/splitbams/<sample>/<sample>.<target>.bam`

9. build_count_matrix
   - Input: 
      1. <bam_dir>
         Absolute path to the directory containing BAM files for this specific sample
      2. <sample>
         (see Global Input Parameters)
      3. <out_dir>
         (see Global Input Parameters)
      4. <ref_genome> 
         (see Global Input Parameters)
      5. <regions>
         Genomic regions to quantify. (default: 800) 
         Specified either as :
            - an integer bin size in base pairs (e.g., 5000 for fixed non-overlapping genome tiles over standard chromosomes, excluding mitochondrial DNA) 
            - an absolute path to a single region file defining custom regions in BED (.bed: 0-based half-open, columns chr,start,end[,gene_id]), TSV/TXT (.tsv/.txt: 1-based inclusive, columns seqnames,start,end[,gene_id]), or CSV (.csv: same columns as TSV)

10. biclustering_wrapper
   - Input:
      1. <count_matrix_files>
         List of absolute path(s) to input count matrix files (.feather)
      2. <group_tag>
         Name of this analysis group, or the sample name when only a single sample is provided.
         Used as a subdirectory name under `<out_dir>/bicluster/` to organize outputs per group/sample. If not explicitly provided by the user, infer a reasonable value automatically. (required)
      3. <out_dir>
         (see Global Input Parameters)
      4. <ref_genome>
         (see Global Input Parameters)
      5. <filter_method>
         String selecting the region-filtering strategy applied before biclustering. (default: "top_pct")
            Must be one of: "top_pct", "hvr", "none"
            - "top_pct": percentile-based union filtering across pairs (default; general-purpose).
            - "hvr": highly-variable-region filtering.
            - "none": skip filtering, recommended when using user-defined specific genomic intervals (e.g. custom regions in build_count_matrix).
      6. <no_annotation>
         Boolean flag controlling annotation (default: False)
            - set to False (default) to annotate genome-bin–based count matrices
            - set to True to skip annotation when using user-defined genomic intervals ie when using custom regions in build_count_matrix 
      7. <no_plot>
         Boolean flag If True, disable plotting (default: False) 
      8. <row_km>: Number of k-means clusters for rows (regions). (default: 15)
      9. <col_km>: Number of k-means clusters for columns (CRF pairs). (default: 4)
   - Output: 
      1. A dictionary of output paths. Keys included depend on `no_annotation` and `no_plot`:
            Always included
               - "region_cluster" (str):
                  Path to `row_table.tsv`, region-to-row-cluster assignments.
                  Columns: region (`chr_start_end`), cluster label (A, B, C, ...).
               - "pair_cluster" (str):
                  Path to `col_table.tsv`, pair-to-col-cluster assignments.
                  Columns: pair name, cluster label (1, 2, 3, ...).

            Included only when `no_plot` is False
               - "heatmap" (str):
                  Path to the biclustering heatmap PDF produced by the R pipeline
                  (filename depends on the underlying `biclustering()` implementation).

            Included only when `no_annotation` is False AND `no_plot` is False
               - "TFBS_enrichment_heatmap" (str):
                  Path to the TFBS enrichment heatmap PDF under `<out_dir>/bicluster/<group_tag>/TFBS_enrichment/`.
               - "distribution_plots" (List[str]):
                  List of stacked barplot PDFs found under `<out_dir>/bicluster/<group_tag>/genomic_distribution`, one per genomic annotation layer
   - Function
      Performs biclustering on one or more Feather-format count matrices by optionally filtering HVRs, clustering genomic regions and features with k-means, and optionally annotating biclusters with genomic summaries, TFBS enrichment, and diagnostic plots.
      This function supports joint analysis across multiple samples. When samples belong to the same analysis group (typically those from the same experimental condition or biological replicates), all corresponding count matrices must be provided together in <count_matrix_files> as a list. Samples from different conditions are generally treated as separate groups and should each trigger an independent call to this function
      The biclustering model is built on the combined matrices to learn shared genomic region patterns and CRF-pair relationships across samples. The function should therefore be executed once per analysis group, not separately for each sample.
      **This function should only be called when the user explicitly requests biclustering analysis. Do not invoke it as part of a default or assumed workflow.**
   - Path Convention (relative to <out_dir>):
      Creates and writes into:
      - `bicluster/<group_tag>/`
      Key outputs in this folder:
      - `row_table.tsv`
      - `col_table.tsv`
      - `biclustering_heatmap.pdf` (if plotting enabled)
      Optional subdirectories:
      - `TFBS_enrichment/`
      - `genomic_distribution/`

11. differential_analysis
   - Input:
      1. <count_matrix_files>
         List of absolute paths to per-sample count matrix files (.feather), one per sample.
         Must be the same length as <conditions> and in the exact same order — count_matrix_files[i] belongs to conditions[i].
      2. <conditions>
         Condition label for each sample, in the same order as <count_matrix_files>.
         Each unique condition must appear at least twice (≥2 replicates).
         All pairwise comparisons are derived automatically (sorted alphabetically, in the form <test>_vs_<ref>).
      3. <out_dir>
         (see Global Input Parameters)
      4. <sample_names>
         Optional unique display names for each sample, in the same order as <count_matrix_files>. (default: None)
         If None, auto-generated as <condition><replicate_index> (e.g. "C1", "C2", "T1").
      5. <col_cluster_file_path>
         Optional path to the col_table.tsv produced by biclustering_wrapper, with columns `pair` and `cluster`. (default: None)
         When provided, CRF pairs assigned to the same cluster are aggregated before testing.
         When None (default), each CRF pair is tested independently as its own comparison unit.
         Note: only provide this when a prior biclustering step has been performed; omit otherwise.
      6. <ref_genome>
         (see Global Input Parameters)
      7. <min_support>
          Minimum number of samples a peak must appear in to be retained in the consensus set. (default: 2)
      8. <lfc_threshold>
          Log2 fold-change threshold for significance. (default: 0.5)
      9. <p_threshold>
          P-value threshold for significance. (default: 0.05)
      10. <p_type>
          Which p-value to use for filtering: "fdr" (BH-adjusted, recommended for genome-wide analysis and whole-transcriptome analysis),
          "nominal" (raw p-value, suitable for pre-selected gene lists), or "bonferroni" (conservative correction).
          (default: "fdr")
      11. <no_annotation>
         Boolean flag controlling GREAT-based pathway enrichment analysis of significant differential regions (default: False)
         - set to False to perform pathway enrichment analysis on regions passing the significance criteria
         - set to True to skip enrichment analysis
      12. <no_plot>
         Boolean flag controlling plot generation (default: False)

   - Output:
      A dictionary of output paths. Keys included depend on `no_annotation` and `no_plot`.

      Always included:
         - "sig_regions" (Dict[str, List[str]]):
            Per-group significant region tables, one file per comparison (only written when ≥1 significant region exists).
            Keys are group names (cluster1/cluster2/... or CRF pair names).
            Path format: `<out_dir>/differential/<comparison>/<group>_sig.tsv`
            Columns: pos, logFC, AveExpr, t, P.Value, adj.P.Val, B
         - "sig_summary" (List[str]):
            Per-comparison filtering and significance count summary tables.
            Path format: `<out_dir>/differential/<comparison>/summary.tsv`
            Columns: group, n_rows_before, n_rows_after_nonzero, n_rows_after_mean, n_sig, n_up, n_down

      Included only when `no_plot` is False:
         - "sig_summary_barplot" (List[str]):
            Per-comparison mirror bar chart PDFs (up-regulated in red, down-regulated in blue).
            Path format: `<out_dir>/differential/<comparison>/summary.pdf`

      Included only when `no_annotation` is False AND `no_plot` is False:
         - "pathway_annotation_bubbleplots" (List[str]):
            Per-comparison bubble plot PDFs summarising enrichment across all groups.
            Path format: `<out_dir>/differential/<comparison>/pathway_annotation/pathway_annotation.pdf`

   - Function:
      Identifies differentially accessible genomic regions between conditions using a two-round limma-voom framework.
      Comparisons are automatically derived from all unique values in <conditions> and run pairwise.
      A subdirectory is created per comparison under `<out_dir>/differential/`.
      When <col_cluster_file_path> is provided (i.e. after a biclustering step), CRF pairs within the same cluster
      are aggregated before testing; otherwise each CRF pair is tested independently.
      Optionally generates heatmaps for significant regions and GREAT-based pathway enrichment annotations per comparison.

   - Path Convention (relative to <out_dir>):
      differential/<comparison>/<group>_all.tsv
      differential/<comparison>/<group>_sig.tsv          (only when ≥1 significant region)
      differential/<comparison>/<group>_sig_counts.tsv   (only when ≥1 significant region)
      differential/<comparison>/summary.tsv
      differential/<comparison>/summary.pdf              (only when no_plot is False)
      differential/<comparison>/pathway_annotation/pathway_annotation.pdf            (only when no_annotation is False AND no_plot is False)

12. peak_profiling
   - Input:
      1. <bedgraph_dir>
         Absolute path to the directory containing bedGraph files for the specific sample
      2. <sample>
         (see Global Input Parameters)
      3. <out_dir>
         (see Global Input Parameters)
      4. <ref_genome>
         (see Global Input Parameters)
      5. <min_cov>
         Minimum mean coverage (auc/length) pre-filter applied to candidate peak blocks before statistical testing. (default: 2.0)
      6. <auc_top_pct>
         Top percentile of blocks by AUC retained before statistical testing. Must be in (0, 1]. (default: 0.1)
      7. <qvalue_cutoff>
         BH-adjusted q-value threshold for peak filtering. (default: 0.05)
      8. <fc_cutoff>
         Fold-change threshold for peak filtering. (default: 2.0)
      9. <no_annotation>
         Boolean flag controlling GREAT-based pathway enrichment analysis of peak regions (default: False)
      10. <no_plot>
         If True, suppress all plot outputs. (default: False) 
   - Output: 
      1. A dictionary of output paths. Keys included depend on `no_annotation` and `no_plot`:
            Always included
               - 'peak_dir' (str):
                  Path to the directory `<out_dir>/peak/<sample>/`, containing one narrowPeak file per input bedGraph file with names `{bedgraph_prefix}_peaks.narrowPeak`. 
               - 'log_out': 
                  (see Global Output Parameters)

            Included only when `no_annotation` is False AND `no_plot` is False
               - "TFBS_enrichment_heatmap" (str):
                  Path to the TFBS enrichment heatmap PDF under `<out_dir>/bicluster/<group_tag>/TFBS_enrichment/`.
               - 'pathway_annotation_bubbleplot' (str):

   - Function:
      Runs a two-step pipeline: (1) peak calling from bedGraph coverage files, identifying significant signal blocks and writing narrowPeak outputs; (2) optional annotation on called peaks, including genomic distribution summaries, rGREAT-based MSigDB pathway enrichment, and TFBS enrichment analysis.
   - Path Convention (relative to <out_dir>):
      Creates and writes into:
      - `peak/<sample>/`   (this is the returned 'peak_dir')
      Optional subdirectory (when no_annotation is False):
      - `peak/<sample>/pathway_annotation/`
      - `peak/<sample>/TFBS_enrichment/`
      - `peak/<sample>/genomic_distribution/`

13. peak_differential_analysis
   - Input:
      1. <peak_dirs>
         List of per-sample directories containing narrowPeak files (order must match conditions).
      2. <bam_dirs>
         List of per-sample directories containing BAM files (order must match conditions).
      3. <conditions>
         Condition labels, one per sample (order must match peak_dirs and bam_dirs).
      4. <out_dir>
         (see Global Input Parameters)
      5. <sample_names>
         Optional sample name list. Auto-generated if None. (default: None)
      6. <ref_genome>
         (see Global Input Parameters)
      7. <bam_pattern>
         Regex pattern used to match BAM filenames. (default: "\.bam$")
      8. <peak_pattern>
         Regex pattern used to match narrowPeak filenames. (default: "_peaks\.narrowPeak$")
      9. <window_size>
         Window size for peak merging. None uses automatic sizing. (default: None)
      10. <min_support>
          Minimum number of samples a peak must appear in to be retained in the consensus set. (default: 2)
      11. <lfc_threshold>
          Log2 fold-change threshold for significance. (default: 0.5)
      12. <p_threshold>
          P-value threshold for significance. (default: 0.05)
      13. <p_type>
          Which p-value to use for filtering: "fdr" (BH-adjusted, recommended when the peak set is derived from a genome-wide consensus),
          "nominal" (raw p-value, suitable when peaks are restricted to a pre-selected set of regions), or "bonferroni" (conservative correction).
          (default: "fdr")
   - Output:
      1. A dictionary containing:
         - 'sig_regions' (defaultdict[str, List[str]]): Per-comparison significant region TSVs, keyed by cmp_tag (e.g. "B_vs_A").
         - 'sig_summary' (List[str]): Per-comparison summary TSVs.
         - 'log_out': (see Global Output Parameters)
   - Function:
      Runs a two-step pipeline per condition pair: (1) merges per-sample narrowPeak files into a consensus region BED using a minimum support threshold; (2) counts BAM fragments over consensus regions and runs limma-voom to identify differentially accessible regions per condition pair.
   - Path Convention (relative to <out_dir>):
      Creates and writes into:
      - `peak/differential/<cmp_tag>/`
         Key outputs in this folder:
         - `summary.tsv`
         - `*_sig.tsv` (one per significant contrast)
